## 二、功能升级：请求参数与响应参数 JSON 语法高亮实现

### 1. 业务痛点
在此前版本中，请求体与响应体在 `JSON Text` 选项卡下虽然进行了排版缩进，但代码文本为单色纯文本（灰色/白色），不易快速区分属性键、字符串、数值、布尔值和标点符号；且某些接口的 Query 参数中嵌套了 JSON 字符串，在参数表格中排版混乱。

### 2. 技术实现方案
- **分词器设计 (`public/js/utils/formatters.js`)**：
  采用线性时间复杂度的正则匹配机制：
  ```javascript
  const tokenRegex = /("(?:\\.|[^"\\])*"(?:\s*:)?|\b(?:true|false|null)\b|-?\d+(?:\.\d*)?(?:[eE][+\-]?\d+)?|[{}\[\]:,])/g;
  ```
  - `"(?:\\.|[^"\\])*"`：严格匹配任意含转义字符的双引号字符串，无灾难性回溯风险；
  - `(?:\s*:)`：识别 JSON Object 的键名（Key），将其与后续冒号分离，赋予 `.tok-key` 样式；
  - `\b(?:true|false|null)\b`：精准识别布尔值与空值；
  - `-?\d+...`：匹配整数、浮点数与科学计数法。
- **色彩设计与主题自适应 (`public/style.css`)**：
  - **Dark 模式**：键名 `#d2a8ff` (淡紫)、字符串 `#7ee787` (淡绿)、数值 `#79c0ff` (浅蓝)、布尔 `#ff7b72` (珊瑚红)、空值 `#8b949e` (斜体灰)。
  - **Light 模式**：自动匹配深紫、深绿、深蓝与深红，保持极高对比度。
- **Query 参数智能高亮**：
  当 Query 表格中的某个值符合 `{...}` 或 `[...]` 特征且解析有效时，自动以内嵌卡片高亮代码块展示。
- **防御性降级保护**：
  对超过 2MB 的极端特大 JSON 数据自动退化为安全转义的纯文本输出，杜绝海量 DOM 节点导致页面卡死。

## 三、深度分析：Client network socket disconnected before secure TLS connection was established 异常原因

### 1. 异常本质
该报错由 Node.js 原生底层 `tls_wrap` 模块抛出，经代理引擎 `Mockttp` 打印至控制台。字面含义为：
> **“在与对端完成安全 TLS 加密连接握手（Client Hello / Server Hello）之前，底层 TCP Socket 便被对端单方面主动断开（发送了 FIN 或 RST）。”**

### 2. 5 大典型诱发原因
1. **客户端启用了 SSL Pinning（证书双向锁定）**：
   - 目标 App（如银行、微信小程序、TikTok 等）写死了官方公钥。当抓包代理出示自签名 CA 证书时，App 校验失败，立即单方面掐断连接。
2. **设备尚未信任根证书**：
   - 手机虽然下载了证书，但未进入系统「关于本机 -> 证书信任设置」开启完全信任。
3. **系统后台长连接探活（系统级静默请求）**：
   - iOS 的 APNs 推送通道、iCloud 同步，Android 的 Google Play 探活等私有服务，在后台每隔十几秒会向专用端口发起探活，这些通道走代理时必定被系统强行断开。
4. **外部上游代理端口错误或未启动**：
   - 本地开启了上游代理（如 7890 端口），但 Clash/VPN 软件并未运行，或将 SOCKS5 端口误配为了 HTTP 代理。
5. **目标服务端启用了防爬/WAF 拦截**：
   - 如 Cloudflare 检测到底层非浏览器 TLS 指纹直接 `TCP RST` 挂断。

### 3. 治理方案
该现象在网络真实通信与移动端后台机制中属于正常波动。在 `index.js` 中将其补充进 `IGNORED_PATTERNS` 过滤白名单，避免控制台刷屏，恢复清爽的调试环境。

## 四、架构延展：除 MITM 之外的 5 种主流抓包方式深度剖析

| 抓包方式 | 核心技术原理 | 对 HTTPS 的解密方案 | 能否穿透 SSL Pinning | 客户端感知度 | 典型适用场景 |
| :--- | :--- | :--- | :---: | :---: | :--- |
| **MITM 代理 (本项目)** | 本地 HTTP/SOCKS 代理 + 动态伪造 CA 根证书重新签发 | 代理作为中间人双向协商 TLS | ❌ 需配合破解插件 | 需配代理与证书 | 日常 API 调试、接口 Mock、前端联调 |
| **内存 Hook 探针** | 利用 Frida / Xposed 注入进程内存空间 | 直接截获加密前 / 解密后的明文数据 | **✅ 完美穿透** | 完全无感 | 逆向工程、安全渗透、强防护 App 破解 |
| **内核 eBPF 探针** | Linux 内核 uprobe/kprobe 挂钩 OpenSSL / BoringSSL 动态库 | 在用户态数据传入加解密前直接抄送副本 | **✅ 完美穿透** | 完全无感 | 服务端微服务观测 (eCapture/Pixie)、无感运维 |
| **VPN / TUN 虚拟网卡** | 通过 Android VpnService 或桌面 TUN 网卡接管 IP 报文 | 本地路由拦截并建立虚拟网络处理隧道 | ❌ 需配合证书 | 系统全局生效 | 抓取 Flutter、游戏 UDP 等不走系统代理的应用 |
| **网络层嗅探 (Wireshark)** | 网卡混杂模式抓取原始以太网帧 (PCAP) | 配合客户端 `SSLKEYLOGFILE` 预主密钥无损解密 | **✅ 真实证书解密** | 完全无感 | TCP 握手诊断、底层弱网排查、丢包分析 |

## 五、技术论证：Node.js 实现 Wireshark 抓包分析能力的可行性

**结论：完全可行。**

1. **报文捕获能力**：
   - 可通过 `libpcap` 原生绑定（如 `cap`、`node_pcap` 库）调用网卡混杂模式；
   - 亦可直接流式管道唤起 `tcpdump -w -`，在 Node.js 中以事件流逐包接收原始以太网数据。
2. **协议解码与重组**：
   - 依赖 Node.js 高效的 `Buffer` 二进制操作，可以精准拆解 Ethernet Frame ➔ IPv4/IPv6 ➔ TCP/UDP ➔ DNS/HTTP 各层头部；
   - 支持解析 TCP Seq/Ack 号完成流重组（Stream Reassembly）。
3. **PCAP 格式读写**：
   - PCAP 协议头仅 24 字节 + 每包 16 字节头部，Node.js 可毫秒级导出标准 `.pcap` 文件，兼容官方 Wireshark 打开。
4. **边界与权衡**：
   - **优势**：极佳的 Web/B-S 架构兼容性、远程无头抓包敏捷性、自研私有协议解析极快。
   - **短板**：在超万兆大流量（数十万 PPS）下受 V8 垃圾回收限制存在丢包风险；且不如 Wireshark 具备 3000+ 工业协议的现成积累。
